# Plan: Allow duplicate callsigns in reports

## Context
Currently `signal_reports` has a `UNIQUE (exercise_id, operator_id, repeater_id)` constraint — same callsign can only appear once per repeater per exercise. User wants to allow the same callsign multiple times (e.g. operator checks in again later with different signal conditions).

## Changes

### 1. Schema: `server/src/db/schema.ts`
- Add migration: detect the UNIQUE constraint and recreate `signal_reports` without it
- Use PRAGMA index_list + PRAGMA index_info to find the constraint, then recreate table via `signal_reports_new` pattern (copy data, drop old, rename)
- Keep all columns, indexes, just drop the UNIQUE constraint

### 2. Server: `server/src/routes/exercises.ts`
- **POST `/:id/reports`** (~line 290): Remove the `catch` block that handles UNIQUE constraint violations (the 409 response with `existing_report`). Without the constraint, inserts will just succeed.

### 3. Client: `client/src/components/BundMode.tsx`
- **`handleBezirkSubmit`** (~line 190): Remove the inner try/catch that catches 409 and patches existing report. Just do the POST — it will always create a new report now.

### 4. Client: `client/src/components/LandMode.tsx`
- **`handleBezirkSubmit`** (~line 131): Same removal — remove the inner try/catch 409 handling.

### 5. Stats query: `server/src/routes/exercises.ts`
