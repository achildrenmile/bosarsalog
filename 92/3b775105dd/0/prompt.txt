# Übungstyp (Exercise Type) Field

## Context
Exercises currently have only a `name` field used both as type and title. The user needs a dedicated `exercise_type` field to distinguish between "Krisenkommunikationsübung" and "80m Notfunk Runde" (and future types). This enables filtering in Auswertungen by type (multi-select or all). Existing data must be backfilled correctly.

## Changes

### 1. Shared Constants
**NEW `client/src/constants/exerciseTypes.ts`**

```typescript
export const EXERCISE_TYPES = [
  { value: 'Krisenkommunikationsübung', label: 'Krisenkommunikationsübung', short: 'KriKom' },
  { value: '80m Notfunk Runde', label: '80m Notfunk Runde', short: 'Notfunk' },
];
export const DEFAULT_EXERCISE_TYPE = 'Krisenkommunikationsübung';
export function getShortLabel(type: string) { ... }
```

### 2. Schema Migration
**`server/src/db/schema.ts`** — after line 207 (organisator migration)

- `ALTER TABLE exercises ADD COLUMN exercise_type TEXT DEFAULT 'Krisenkommunikationsübung'`
- Backfill: `UPDATE exercises SET exercise_type = '80m Notfunk Runde' WHERE name LIKE '%Notfunk%'`

### 3. API: Exercises CRUD
**`server/src/routes/exercises.ts`**

- **GET /exercises**: Add `e.exercise_type` to SELECT (line 12)
- **POST /exercises**: Accept `exercise_type` in body, include in INSERT (lines 22, 29)
- **PATCH /exercises/:id**: Add `exercise_type` to dynamic updates (lines 80-86)

### 4. API: Aggregated Reports Filter
**`server/src/routes/reports.ts`**

- Accept optional `types` query param (comma-separated)

- Include `e.exercise_type` in exercises SELECT
