# Issue #6: Rufzeichen doppelt eingeben führt zu Problemen

## Context
Wenn ein Rufzeichen doppelt eingegeben wird (gleicher Operator + gleicher Repeater in derselben Übung), greift die UNIQUE-Constraint der DB und der Server gibt 409 zurück. Der Client fängt den Fehler ab und versucht den existierenden Report per `reports.find()` im lokalen State zu finden, um ihn zu PATCHen. Wenn der Report im Client-State nicht gefunden wird (z.B. stale State), passiert **gar nichts** — kein Feedback, kein Update. Das ist der Hauptbug.

## Lösung: Server gibt existierenden Report bei 409 zurück

Statt nur eine Fehlermeldung zurückzugeben, liefert der Server bei Duplikat-Erkennung den **existierenden Report** mit. Der Client kann dann direkt damit arbeiten, ohne im lokalen State suchen zu müssen.

### 1. Server — `server/src/routes/exercises.ts` (POST /:id/reports, Zeile 280-286)

Im `catch`-Block bei UNIQUE-Violation: den existierenden Report aus der DB laden und als `existing_report` im 409-Response mitsenden.

```js
if (e.message?.includes('UNIQUE')) {
  const existing = db.prepare(`SELECT sr.*, o.callsign, ... WHERE sr.exercise_id = ? AND sr.operator_id = ? AND sr.repeater_id = ?`)
    .get(req.params.id, operator_id, repeater_id);
  res.status(409).json({ error: '...existiert bereits', existing_report: existing });
}
```

### 2. Client — `client/src/services/api.ts` (apiFetch, Zeile 34-36)

`apiFetch` wirft bei `!res.ok` einen Error mit nur `err.error` als Message. Für 409 brauchen wir auch den `existing_report`. Lösung: die volle Error-Response als `data` Property am Error-Objekt anhängen.

```js
if (!res.ok) {
  const err = await res.json().catch(() => ({ error: 'Fehler' }));
  const error: any = new Error(err.error || `HTTP ${res.status}`);
  error.data = err;
  throw error;
}
```

### 3. Client — `client/src/components/LandMode.tsx` (handleBezirkSubmit, Zeile 137-148)

Statt `reports.find()` den Report aus `err.data.existing_report` nehmen:

```js
catch (err: any) {
  if (err.message?.includes('existiert') && err.data?.existing_report) {
    const existing = err.data.existing_report;
    const updated = await apiFetch(`.../${existing.id}`, { method: 'PATCH', body: ... });
    onReportUpdated(updated);
  }
}
```

### 4. Client — `client/src/components/BundMode.tsx` (handleBezirkSubmit, Zeile 146-155)

Gleiche Änderung wie LandMode.
